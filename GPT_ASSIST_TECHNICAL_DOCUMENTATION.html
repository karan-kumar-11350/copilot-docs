1. System Overview
GPT Assist — AI-powered clinical assistance embedded in the Charm EHR physician workflow

GPT Assist is Charm EHR's AI-powered clinical assistance feature. It integrates OpenAI and Azure OpenAI APIs across multiple clinical workflows: chart note generation, referral drafting, lab interpretation, diagnosis suggestions, and general medical Q&A. All features are embedded directly in the physician encounter workflow and operate under HIPAA-compliant PHI masking.

PHI Masking (HIPAA)

Before any patient data is sent to an external AI service, AIUtil.java replaces PHI tokens (patient name, provider name, date of birth) with placeholder strings. The mapping is stored server-side and returned to the client for local unmasking after the AI response is received. Lab opinion is the only workflow that skips PHI masking — lab parameter names and numeric values are not considered PHI.

PHI Masking Pattern: Patient name → [MASKED_PATIENT], Provider name → [MASKED_PROVIDER], DOB → [MASKED_DOB]. The masked_data JSON map is returned to the client and stored in gptReferralAssist.phiUnmaskingData for local replacement after letter generation.

Key design principle: AiAPI.java handles only validation and null-checks. All business logic (PHI masking, prompt construction, DB queries) lives in AIUtil.java. Direct OpenAI calls for simple Q&A go through GPT4Util.java. The HTTP layer is always UrlUtil.java (TLS 1.2, 10s connect / 30s read timeout).

Provider enters API key in Practice Settings and clicks Validate

Detailed Flow

sequenceDiagram participant P as Provider participant UI as settings.js participant SEC as security-api-ai.xml participant AIAPI as AiAPI.java participant GPT4 as GPT4Util.java participant URL as UrlUtil.java participant OAI as OpenAI API P->>UI: validateGPTAPIKey() triggered Note right of UI: reads key from input field UI->>SEC: POST /api/ehr/v1/gpt/check Note right of UI: body: {api_key} SEC->>SEC: Authenticate session + rate limit check SEC->>AIAPI: AiAPI.userModels(apiKey) AIAPI->>GPT4: GPT4Util.fetchUserModels(apiKey) GPT4->>URL: HTTPS GET /v1/models Note right of GPT4: Authorization: Bearer apiKey URL->>OAI: GET https://api.openai.com/v1/models alt Key valid (200) OAI-->>URL: 200 {data:[{id:"gpt-4",...}]} URL-->>GPT4: models list JSON GPT4->>GPT4: check "gpt-3.5-turbo" and "gpt-4" in list GPT4-->>AIAPI: {is_valid:true, gpt_4_enabled:true} else Key invalid (401) OAI-->>URL: 401 {error:{type:"invalid_api_key"}} GPT4-->>AIAPI: {is_valid:false, gpt_4_enabled:false} end AIAPI-->>SEC: JSONObject as String SEC-->>UI: HTTP 200 JSON alt is_valid = true UI-->>P: Green checkmark, key saved on settings submit else is_valid = false UI-->>P: Red error toast end

Business Rules

  1. No DB read or write occurs during key validation — key is only stored when settings are saved separately.
  2. The gpt_4_enabled flag is derived by checking whether the returned models list contains a model whose ID includes "gpt-4".
  3. Presence of "gpt-3.5-turbo" indicates basic key validity; presence of "gpt-4" indicates GPT-4 access.
  4. The rate limit (60/min) applies to the calling provider session, not per API key.

Response Generation

public static String generateResponse(GPT4Request request)
Wrapper: calls generateGPT4Response() and returns choices[0].message.contentAsString(). Use for plain-text AI responses.
public static String generateJSONResponse(GPT4Request request)
Same as generateResponse but validates and extracts JSON from the response. Handles LLM preamble text by finding first { and last }. Replaces {delimiter} with ####. Throws FinanceException(GPT_API_JSON_ERROR) if no valid JSON bracket pair found.
public static GPT4Response generateGPT4Response(GPT4Request request)
Core method. Forces model to GPT_4O. Creates GPT4Api instance with practice API key. Handles null response, empty choices, and known GPT errors (insufficient_quota → specific error code; others → SEVERE log). Logs total tokens at INFO.

Request Building

public static GPT4Request generateGPT4Request(String userData, String appendToUserPrompt, String modelType, String pastTrxns)
Standard request builder. Steps: (1) Get API key via AIUtil.getGptAPiKey(). (2) Call getGPTPromptDetails() for system_prompt, user_prompt, max_tokens. (3) Replace {delimiter} with ####. (4) Call updateUserPrompt() to fill {key} placeholders from userData JSON. (5) Append appendToUserPrompt if provided. (6) If pastTrxns not null: deserialize MessageQueue from Gson JSON, cleanQueue(). (7) Build: [past messages] + systemMessage + userMessage. (8) Return GPT4Request(GPT_4O, messagesList, max_tokens).
public static String[] updateUserPrompt(String userData, String user_prompt)
Uses regex \{(.*?)\} to find {key} placeholders in user_prompt. Parses userData as JSON (ObjectMapper). Replaces matched keys. Preserves {Past*} keys (for multi-turn history). Returns [updated_user_prompt, updated_userData_json] array.

GPT4Message role ("system"|"user"|"assistant"), content (String or List<GPT4Content>) Dual mode: text and vision. getContentAsString() handles both types transparently
GPT4Choice index, message (GPT4Message), finish_reason Use choices[0] for single-response flows
GPT4Content type ("text"|"image_url"|"file"), text, image_url (GPT4ImageUrl), file (GPT4File) Used for multimodal (Vision API) requests
GPT4ImageUrl url (base64 data URL), detail ("high" for medical images) High detail used for medical images requiring precise interpretation
GPT4File file_id, purpose OpenAI Files API reference for pre-uploaded documents
GPT4Usage prompt_tokens, completion_tokens, total_tokens Logged at INFO level; used for usage tracking in AIUtil
GPT4Error message, type, param, code "insufficient_quota" is handled specifically with a dedicated error code
GPT4Constants GPT_3_5_TURBO="gpt-3.5-turbo", GPT_4="gpt-4", GPT_4O="gpt-4o", USER="user", SYSTEM="system", ASSISTANT="assistant" GPT_4O is the forced default for all requests in GPT4Util

CharmCache — GPT Assist Keys

CharmCache (in-memory distributed cache) is used to avoid DB round-trips on hot paths. GPT Assist populates the following cache namespaces.

Cache Key PatternTTLStores
GPT_PROMPT_{PROMPT_TYPE}30 minFull GPTPROMPTDETAILS row for a given prompt type; invalidated on admin update
GPT_API_KEY_{PRACTICE_ID}15 minDecrypted API key; short TTL to limit exposure window on key rotation
GPT_CONV_{SESSION_ID}24 hSerialised MessageQueue for the provider session; keyed by session token
GPT_RATE_{PRACTICE_ID}_{MINUTE_EPOCH}2 minRequest counter for rate limiting; incremented on each API call; evicts naturally after 2 min
Warning: The GPT_API_KEY_{PRACTICE_ID} cache entry holds a plaintext decrypted API key in memory. Cache eviction or server restart will trigger a DB re-fetch and re-decryption. Ensure the AES key used for encryption is stored in a secure properties file outside the WAR.
